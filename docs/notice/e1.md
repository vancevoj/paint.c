# Lane E1 attribution notes (brush engine, Pencil, Clone Stamp, Recolor)

No code was copied or translated from any Paint.NET release. Paint.NET
4.x, 5.x and 6.x were never decompiled or disassembled (P-01, ADR-002);
their behavior was taken from the official documentation mirror, the
release notes and public forum posts by the author. The lane read the
MIT-licensed Paint.NET 3.36.7 source (mirror: github.com/rivy/OpenPDN,
Copyright dotPDN LLC, Rick Brewster, Tom Jackson and contributors, MIT,
see NOTICE) only for the algorithms and behaviors listed here.

| 3.36 file | What was taken | Where it is used |
|---|---|---|
| src/tools/RecoloringTool.cs (DrawOverPoints) | The recolor rule: a pixel within tolerance of the color being replaced gets every color channel shifted by (replacement - replaced), clamped to 0..255, and keeps its own alpha; at a partially covered (antialiased) brush pixel the adjusted color is blended over the pixel by the brush coverage and the alpha is restored. | pc_recolor_pixel, pc_recolor_row (the blend is done by pc_paint_apply in Overwrite mode, which keeps alpha when both pixels share it) |
| src/tools/CloneStampTool.cs | Behavior: when the source layer is the active layer, source pixels come from a copy of the layer saved before painting (no smearing); the take-from point moves with the stroke and persists between strokes until Ctrl+click sets a new one, which is a fixed offset. | pc_clone (pc_txn_original sampling, offset locked by the first stroke) |
| src/tools/PencilTool.cs | Behavior: 1 px aliased lines between successive pointer positions, the start pixel of later segments not drawn again, primary or secondary color with its alpha. | PC_BRUSH_TIP_PENCIL |

Not taken: the 3.36 tolerance restriction of the Recolor tool (it only
prevented recoloring pixels twice while painting in place, which cannot
happen here because every result is computed from the stroke-start
pixels, and it would contradict the 5.1 documentation that 100%
tolerance recolors everything), the 3.36 ColorDifference metric (the core
tolerance metric of pc_fill.h is used instead), the 3.36 line algorithm
(Utility.GetLinePoints rounds late; paint.c uses its own Bresenham with
symmetric rounding), and the 3.36 Paintbrush (a filled polygon per mouse
move with a squared pressure curve).

Everything else is original work of this project: the dab profile and
hardness falloff, the build-up and max accumulation, the arc-length dab
walker with carry, the quadratic B-spline input smoothing, the sparse A8
stroke coverage with per-event change tracking, and the band grouping of
changed tiles for pc_paint_apply.
