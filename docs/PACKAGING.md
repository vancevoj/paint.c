# PACKAGING

How paint.c is packaged for Linux, Windows and macOS, what each package
contains, and how CI builds and releases them (lane I). The files live in
packaging/ (overview: packaging/README.md).

## Common contents

Every package carries:

* the `paintc` executable (`paintc.exe` on Windows, `paint.c.app` on macOS),
  statically linked with SDL3 3.4.18 and the codec libraries when built with
  `-DPC_VENDOR_SDL=ON` (CI does); with a system SDL3 the AppImage bundles
  `libSDL3.so` through linuxdeploy;
* a `licenses` folder: paint.c's MIT `LICENSE.txt`, `NOTICE.txt` (the
  Paint.NET 3.36 attribution) and the texts of every third-party component
  (packaging/licenses, indexed by its README.txt): SDL3, zlib, libspng (with
  the libpng 2.0 license of the code it took from libpng), libjpeg-turbo
  (with the IJG README), libwebp (with PATENTS), Little-CMS, bcdec, bc7enc,
  stb (stb_truetype and stb_dxt) and the Inter font (SIL OFL 1.1);
  tests/app/test_i_packaging.c fails when the folder and its index differ;
* the application icon: an original design (a white pixel dot and a
  color-wheel letter c on a dark blue tile, so ".c"), generated by
  `python3 packaging/icons/make_icons.py` into assets/icons (scalable SVG, a
  heavier small variant for 16 to 32 px, PNGs 16 to 1024, `paintc.ico` with
  PNG entries, `paintc.icns` written by our own encoder) and
  src/app/io/icon_data.c (the 32, 64 and 256 px PNGs for the window icon,
  set with `SDL_SetWindowIcon` at startup). The generated files are
  committed; builds never run the script.

File types: every format the codec registry opens is registered by each
package (PDN, PNG, JPEG, BMP, GIF, TIFF, WebP, TGA, DDS, OpenRaster).
tests/app/test_i_packaging.c compares the installer, the desktop entry, the
AppStream metadata and Info.plist with `pc_codec_list`, so a new codec fails
the test until the packaging knows it.

## Linux

`cmake --install build --prefix <prefix>` installs (packaging/PcPackaging.cmake):

| Path | File |
|---|---|
| bin/paintc | the executable |
| share/applications/org.paintc.paintc.desktop | desktop entry (`Exec=paintc %F`, MIME types, `StartupWMClass=org.paintc.paintc`, the SDL app id) |
| share/mime/packages/org.paintc.paintc.xml | `image/x-paintnet` for `*.pdn` (magic `PDN3`); the other types are in freedesktop.org.xml |
| share/metainfo/org.paintc.paintc.metainfo.xml | AppStream metadata |
| share/icons/hicolor/{16..512}/apps/org.paintc.paintc.png, scalable/apps/org.paintc.paintc.svg | icons |
| share/doc/paintc/licenses/ | licenses |

Distribution packages run `update-desktop-database`, `update-mime-database`
and `gtk-update-icon-cache` as usual.

* **tar.gz**: `cd build && cpack` (CPack TGZ of the install tree).
* **AppImage**: `packaging/linux/build-appimage.sh build dist` installs into
  an AppDir and runs linuxdeploy 1-alpha-20251107-1 (downloaded once,
  SHA-256 checked, cached in `PC_DOWNLOAD_CACHE`), which writes AppRun,
  bundles the shared libraries the binary needs and packs
  `dist/paintc-<version>-linux-x86_64.AppImage`. It works without FUSE
  (`APPIMAGE_EXTRACT_AND_RUN=1`). Verified locally and in CI with
  `--self-test --headless` inside the AppImage.
* **Flatpak**: `flatpak-builder --user --install --force-clean build-flatpak
  packaging/flatpak/org.paintc.paintc.yml`. Runtime org.freedesktop.Platform
  24.08, Wayland with X11 fallback, DRI, home folder access (recent files
  must stay readable across restarts, which the file chooser portal alone
  does not give). The build is offline: the manifest lists the six
  dependency archives of cmake/PcDeps.cmake and cmake/PcCodecDeps.cmake with
  the same URLs and SHA-256, and passes them to CMake through
  `PC_DOWNLOAD_CACHE`. Keep both lists in sync. Not built in CI (untested).

## Windows

`cmake --install build --prefix stage` gives `paintc.exe`, `README.txt`
(packaging/windows/README-portable.txt) and `licenses\`. paintc.exe embeds
the manifest (long paths, UTF-8, per-monitor DPI), the icon (all sizes of
paintc.ico) and version information (src/app/platform/paintc_version.rc.in;
numeric constants, so windres, rc.exe and llvm-rc all build it).

* **Portable zip**: the install tree zipped as
  `paintc-<version>-windows-x64-portable.zip`. Settings live in
  `%APPDATA%\paintc`, autosave copies in `%LOCALAPPDATA%\paintc\State`;
  `--config-dir DIR` keeps settings and autosaves under DIR instead.
* **Installer**: `makensis /DVERSION=<v> /DSTAGE=<abs stage>
  /DOUTFILE=<abs exe> packaging\windows\paintc.nsi` (NSIS 3, Unicode,
  per-machine, 64-bit registry view). It installs to Program Files, adds a
  Start menu shortcut and an uninstaller (Apps & features entry), registers
  the program ids `paintc.Image` and `paintc.pdn`, an "Open with" entry for
  every extension, the RegisteredApplications capabilities (Settings >
  Default apps), `Applications\paintc.exe\SupportedTypes`, and makes .pdn
  open with paint.c when no other program claims it (only that default is
  removed again on uninstall). Other types keep their defaults: Windows asks
  the user. Verified: built with makensis 3.11 from the MinGW build,
  installed and uninstalled silently (`/S`) under Wine 10 with the registry
  checked.

## macOS

The build produces `build/paint.c.app` (ADR-001; src/app/CMakeLists.txt
copies `paintc.app`), with `Contents/Resources/paintc.icns` and the
licenses in `Contents/Resources/licenses`. Info.plist
(src/app/platform/Info.plist.in) declares every document type (system UTIs,
imported UTIs for .pdn and .ora), `LSMultipleInstancesProhibited` (one
instance per user: pal's single instance is not implemented on macOS, and
LaunchServices forwards opened documents as drop events without a window,
which paint.c opens directly) and `NSHighResolutionCapable`.

* **dmg**: `packaging/macos/make-dmg.sh build dist` installs the bundle,
  signs it ad hoc (`codesign --force --deep --sign -`), verifies the
  signature and packs it with an /Applications link into
  `dist/paintc-<version>-macos-<arch>.dmg`. Without a Developer ID the
  first start needs right click > Open (Gatekeeper). Notarization needs a
  Developer ID certificate, the hardened runtime and, for plugins from the
  per-user folder (ADR-008), the `com.apple.security.cs.disable-library-validation`
  entitlement; that is OWNER work.

## CI and releases

`.github/workflows/ci.yml` (existing jobs unchanged, packaging steps added):

| Job | Packages (artifact name) |
|---|---|
| linux-gcc | validates the desktop entry (desktop-file-validate) and the AppStream file, builds the tar.gz and the AppImage, runs the AppImage's self test (`pkg-linux-x86_64`) |
| windows-cl | portable zip and installer (`pkg-windows-x64`); NSIS comes from the runner image or Chocolatey |
| macos-14, macos-15-intel | dmg per architecture (`pkg-macos-14`, `pkg-macos-15-intel`); these jobs still run only on dispatch, tags or `[mac]` commits |

`.github/workflows/release.yml` runs on tags `v*`: it checks that the tag is
`v` plus the project version in CMakeLists.txt, calls ci.yml (so every test
runs, macOS included because the ref is a tag), downloads the `pkg-*`
artifacts, writes SHA256SUMS.txt and creates the GitHub release with all of
them (`gh release create --generate-notes`).

## Out of scope (documented gaps)

* File > Print (Paint.NET: the Windows photo printing wizard) and File >
  Acquire (scanners): not implemented; Print shows disabled, Acquire is
  hidden.
* The AppStream file has no homepage URL until the project has a site
  (`appstreamcli validate` reports `url-homepage-missing`, the only finding).
* No code signing: Windows binaries are unsigned (SmartScreen warns), macOS
  builds are signed ad hoc only.
