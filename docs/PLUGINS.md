# PLUGINS

Effect plugins for paint.c: how to install them, how the plugin system
works, how to write one, and the official optional plugins that ship as
separate downloads. The user guide's page (docs/help/plugins.md, Help >
Plugins in the app) covers the same ground for users; this page also
covers the repository side (building, testing and packaging the official
plugins).

paint.c loads **native** plugins only: a shared library per plugin written
against paint.c's own C interface, `include/fx/fx_abi.h`. Paint.NET's own
plugins are .NET assemblies built against Paint.NET's DLLs; paint.c cannot
load them (running them would need those DLLs, which the Paint.NET license
does not allow in other software, X-04). Popular ones are re-created
natively below, each crediting its original author.

> Plugins run inside paint.c with the same rights as the program. Install
> plugins only from people you trust.

## Installing a plugin

Every plugin is a folder named after it, holding the library
(`<name>.so`, `<name>.dll` or `<name>.dylib`), its README.md and a
screenshot. Copy the folder into a plugins folder and restart paint.c:

| System | Plugins folder (per user) |
|---|---|
| Linux | `~/.local/share/paintc/plugins/` (`$XDG_DATA_HOME/paintc/plugins/` when that is set) |
| Windows | `%APPDATA%\paintc\plugins\` |
| macOS | `~/Library/Application Support/paint.c/plugins/` |
| Any (portable installs) | a `plugins` folder next to the paintc executable |

1. Download the zip of a plugin for your system from the
   [plugins-v1.0.0 release](https://github.com/vancevoj/paint.c/releases/tag/plugins-v1.0.0)
   (or `paintc-plugins-all-...` for all of them).
2. Unzip it into the plugins folder (create the folder if it is missing).
   Each zip holds one top folder per plugin, so the result is
   `.../plugins/<name>/<name>.so` and so on.
3. Restart paint.c. The plugin's effects appear in the Effects or
   Adjustments menu; their tooltip names the plugin, its author and version.

paint.c loads every library in the plugins folder and in its direct
subfolders. **Effects > Plugin Errors...** lists files it could not load and
why (Settings > Plugin Errors has a button that opens the folder).
`paintc --disable-plugins` starts without any plugin. To uninstall a plugin,
delete its folder.

Checking a download: `SHA256SUMS` on the release page lists the SHA-256 of
every zip (`sha256sum -c SHA256SUMS --ignore-missing` on Linux,
`Get-FileHash <zip>` in PowerShell).

Linux builds are made in Ubuntu 20.04 and need glibc 2.31 or newer, like the
AppImage. Windows builds are 64-bit and need only the system C runtime
(UCRT, Windows 10 and later). macOS plugins are not part of the release yet:
build them from source (below). On Apple silicon every library needs a
signature: the linker adds an ad hoc one, and
`codesign --force --sign - <name>.dylib` renews it after the file changed.

## The official optional plugins

These live in `plugins/<name>/` of this repository and are released as
separate downloads, so paint.c itself stays lean. Each one is a native,
independent re-creation of a popular Paint.NET plugin, made from its public
description (forum posts, help text, screenshots), or ported from source
the original author published under a permissive license (the Basis
column; the license text then ships as LICENSE-original.txt). Credit for
the designs goes to the original authors; their READMEs say more.

## How the plugin system works

* **Loading** (src/app/fx/afx_plugins.c, ADR-008, ADR-018). At startup
  paint.c scans the per-user plugins folder and the portable one: files
  first, then one level of subfolders, in name order. A file is loaded
  with the platform loader (Windows: `LoadLibraryExW` with explicit search
  flags, X-18) and must export `fx_entry`. When it also exports
  `fx_abi_version`, a value other than `FX_ABI_VERSION` rejects the library
  before any of its code runs. `fx_entry` registers effects into a scratch
  registry; each one must pass `fx_effect_validate` (struct size, id and
  menu syntax, property kinds, offsets, ranges, defaults, hints). Loading
  is all or nothing per file, an id that is already taken (by a built-in
  effect or another plugin) is refused, and every problem becomes a Plugin
  Errors entry. Libraries stay loaded until paint.c exits.
* **Running** (ADR-005, the full-source model). For each run paint.c copies
  the active layer into `src` (BGRA, 8 bits per channel, straight alpha,
  the whole layer) and gives the effect a `dst` of the same size. It calls
  `render` for 64 x 64 pixel rectangles (ROIs) of the selection bounds, on
  several worker threads at once, nearest to the view first. `render` may
  read any `src` pixel and writes only the `dst` pixels of its ROI. The
  result must depend only on the parameters, the source and the pixel
  position, never on the ROI split or call order (seeded randomness uses
  the seed parameter and pixel coordinates), and `render` polls
  `host->cancelled(job)` at least once per row. An optional `prepare` runs
  once before the first `render` to build shared tables or statistics;
  `release` frees them. paint.c blends `dst` into the layer through the
  selection (except for `FX_FLAG_NO_SEL_CLIP` effects such as shadows),
  shows it as a live preview and records one History item on OK.
* **The dialog** is built from the effect's `fx_prop` list: sliders,
  check boxes, drop-downs, color wheels, angle dials, point pads and seed
  buttons. `include/fx/fx_widgets.h` adds a position-grid widget and
  tooltips, `host->notice` shows a message when the effect has nothing to
  do (ADR-024). Hosts that do not know an extra show the plain control.
* **Memory and threads**: plugins allocate what they share with paint.c
  with `host->alloc` and free it with `host->free` (X-17, one heap on
  Windows). `render` runs concurrently; keep it free of changing global
  state.
* **Compatibility**: structs carry their size and only grow at the end, so a
  plugin built for ABI v1 keeps working with later paint.c versions of ABI
  v1, and the additions of v1.1 and v1.2 are checked by size before use.

## Writing a plugin

A plugin needs only `fx_abi.h` (and, if you like, the header-only helpers of
`fx_util.h` and `fx_widgets.h`) from `include/fx`; it links no paint.c
code. This complete plugin adds **Effects > Examples > Darken** with one
slider (the paint.c tests build exactly this file and run it through the
plugin loader and the effect checks below, so it stays correct):

<!-- include:begin tests/plugins/minimal_plugin.c -->
```c
/* darken.c - a minimal paint.c effect plugin: Effects > Examples > Darken.
 * Build (fx_abi.h from paint.c's include/fx next to it or on the -I path):
 *   cc -std=c17 -O2 -shared -fPIC -fvisibility=hidden -o darken.so darken.c */
#include <stddef.h>
#include <stdint.h>

#include "fx_abi.h"

typedef struct darken_params {
    int32_t amount;                         /* percent, 0..100 */
} darken_params;

/* One dialog control per property: key, label, kind, offset, min, max,
 * default, step, choices, hint, blob size, flags, enabling condition. */
static const fx_prop k_props[] = {
    { "amount", "Amount", FXP_INT, (uint32_t)offsetof(darken_params, amount), 0.0, 100.0,
      50.0, 1.0, NULL, NULL, 0u, FXP_F_PERCENT, NULL },
};

/* Writes the pixels of roi (BGRA, straight alpha); may run on many threads. */
static int darken_render(const void *params, const void *state, const fx_img *src,
                         fx_img *dst, fx_rect roi, const fx_env *env, const fx_host *host,
                         const void *job)
{
    const darken_params *p = (const darken_params *)params;
    int32_t keep = 100 - (p->amount < 0 ? 0 : (p->amount > 100 ? 100 : p->amount));
    (void)state;
    (void)env;
    for (int32_t y = roi.y; y < roi.y + roi.h; y++) {
        const uint8_t *s = src->px + (size_t)(y - src->r.y) * (size_t)src->stride +
                           (size_t)(roi.x - src->r.x) * 4u;
        uint8_t *d = dst->px + (size_t)(y - dst->r.y) * (size_t)dst->stride +
                     (size_t)(roi.x - dst->r.x) * 4u;
        if (host->cancelled(job)) return FX_CANCELLED;          /* once per row */
        for (int32_t x = 0; x < roi.w; x++, s += 4, d += 4) {
            d[0] = (uint8_t)((s[0] * keep + 50) / 100);         /* blue */
            d[1] = (uint8_t)((s[1] * keep + 50) / 100);         /* green */
            d[2] = (uint8_t)((s[2] * keep + 50) / 100);         /* red */
            d[3] = s[3];                                        /* alpha */
        }
    }
    return FX_OK;
}

static const fx_effect k_darken = {
    sizeof(fx_effect), "com.example.darken", "Effects/Examples/Darken",
    k_props, 1u, (uint32_t)sizeof(darken_params), 0u,
    NULL, NULL, NULL, darken_render               /* init_params, prepare, release */
};

FX_EXPORT uint32_t fx_abi_version(void);
FX_EXPORT const char *fx_plugin_info(const char *key);
FX_EXPORT int fx_entry(const fx_host *host, int (*reg)(const fx_effect *fx));

FX_EXPORT uint32_t fx_abi_version(void) { return FX_ABI_VERSION; }

FX_EXPORT const char *fx_plugin_info(const char *key)      /* the menu tooltip */
{
    if (key && key[0] == 'a') return "Your Name";            /* "author" */
    if (key && key[0] == 'v') return "1.0.0";                /* "version" */
    return NULL;
}

FX_EXPORT int fx_entry(const fx_host *host, int (*reg)(const fx_effect *fx))
{
    (void)host;
    return reg(&k_darken) >= 0 ? 1 : -1;
}
```

Build it for the same architecture as paint.c and copy the library into a
plugins folder (in a folder of its own, or directly):

| System | Command |
|---|---|
| Linux | `cc -std=c17 -O2 -shared -fPIC -fvisibility=hidden -I include/fx -o darken.so darken.c` |
| macOS | `cc -std=c17 -O2 -dynamiclib -fvisibility=hidden -I include/fx -o darken.dylib darken.c` |
| Windows (MinGW) | `x86_64-w64-mingw32-gcc -std=c17 -O2 -shared -I include/fx -o darken.dll darken.c` |
| Windows (Visual Studio) | `cl /std:c17 /O2 /LD /I include\fx darken.c /Fe:darken.dll` |

More: the property kinds and flags are described in docs/help/plugins.md,
a larger example with a color is docs/help/fade_plugin.c, and
tests/plugins/sample_plugin.c uses choices, colors and `fx_util.h`.

### An official plugin in this repository

The contributor's checklist is plugins/README.md: a folder
`plugins/<name>/` with a `CMakeLists.txt` calling
`pc_add_plugin(<name> <sources>)`, a README.md that starts with a
`paintc-plugin` card and credits the original author, a `screenshot.png`
(`packaging/plugins/screenshot.sh` makes one), a `LICENSE-original.txt` when
code was ported from permissively licensed source, and tests in
`tests/plugins/plg_<name>.cmake` with `pc_plugin_test`. `test_plg_all` runs
every effect of every built plugin with default parameters on a photo, a
selection, a transparent layer and an object (no crash, deterministic, the
same result for every ROI split and thread count, writes only inside its
ROI, observes cancellation, fast enough). `python3
packaging/plugins/plugin_meta.py write` refreshes the tables on this page
and in README.md (CTest `test_plg_docs` fails while they are stale).

Legal rules for official plugins (docs/RULES.md P-01, P-02, X-01, X-04):
never decompile, disassemble or inspect the code of a Paint.NET plugin
binary or of Paint.NET itself. Behavior comes from the plugin's public
documentation, forum posts, screenshots, help text and videos; source code
only when its author published it under a license that permits reuse (MIT,
BSD, Apache, zlib, public domain or explicit permission), with the license
and URL recorded in the README card and the license text in
LICENSE-original.txt. No Paint.NET or plugin assets, icons or text.

## Packaging and releasing

`packaging/plugins/build-plugins.sh <build dir> <out dir> [<platform>]`
builds and packages every plugin:

```sh
# Linux x86_64: built in the Ubuntu 20.04 container of the AppImage
packaging/plugins/build-plugins.sh /tmp/plg-linux dist-plugins linux-x86_64
# Windows x64: cross built with mingw-w64
packaging/plugins/build-plugins.sh /tmp/plg-win dist-plugins windows-x64
```

It configures a plugins-only build (`PC_HEADLESS=ON`, no tests) when the
build folder is new, checks every library (exports `fx_entry`; Linux: no
glibc symbol newer than 2.31, no C++ runtime, only glibc libraries;
Windows: only KERNEL32 and the UCRT, no MinGW runtime DLLs) and writes
`paintc-plugin-<name>-<version>-<platform>.zip` per plugin,
`paintc-plugins-all-<version>-<platform>.zip` and `SHA256SUMS` (both
platforms when they share the out folder). The zips are reproducible. The
plugin set version and the GitHub repository of the download links are in
`packaging/plugins/release.conf`.

Release: run both commands into one folder, then
`gh release create plugins-v1.0.0 dist-plugins/*.zip dist-plugins/SHA256SUMS
--title "paint.c plugins 1.0.0" --notes "..."`. The links in this page and
in README.md point at those asset names.
